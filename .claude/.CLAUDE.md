## Working with This Project

### Development Workflow

1. **Creating New Content**
   ```bash
   # Create new blog post
   hugo new content/posts/my-new-post.md

   # Create new tutorial
   hugo new content/tutorials/my-tutorial.md

   # Create new project
   hugo new content/projects/my-project.md
   ```

2. **Local Development**
   ```bash
   # Start Hugo development server
   hugo server -D

   # Build the site
   hugo
   ```

3. **Logging Changes**
   - Use the `hugo-log-manager` skill to track all changes
   - See `.claude/skills/hugo-log-manager/` for scripts
   - Logs are stored in `.claude/DEVELOPMENT_LOG.md` and `.claude/CONTENT_LOG.md`

### Log Management

#### Adding Log Entries

```bash
# Auto-detect change type from git status
python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "Description of change"

# Explicitly specify type
python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "New blog post" --type content
python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "Theme update" --type dev

# Add tags for better organization
python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "Fixed bug" --tags bug,mobile
```

#### Searching Logs

```bash
# Search for keyword
python .claude/skills/hugo-log-manager/scripts/search_logs.py "theme"

# Filter by type
python .claude/skills/hugo-log-manager/scripts/search_logs.py --log dev

# Filter by date
python .claude/skills/hugo-log-manager/scripts/search_logs.py --since 2024-01-01
```

#### Generating Summaries

```bash
# Last 7 days
python .claude/skills/hugo-log-manager/scripts/summarize_logs.py

# Last 30 days grouped by type
python .claude/skills/hugo-log-manager/scripts/summarize_logs.py --days 30 --group-by type
```

## Common Tasks

### 1. Writing a New Blog Post

When the user asks to create a new blog post:
1. Create the markdown file in `content/posts/`
2. Include proper frontmatter (title, date, draft, tags, categories)
3. Add content with appropriate markdown formatting
4. Log the change: `python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "New blog post: [title]" --type content --tags blog`

### 2. Updating Site Configuration

When modifying `hugo.yaml`:
1. Make the requested changes
2. Test locally with `hugo server`
3. Log the change: `python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "Updated [config aspect]" --type dev --tags config`

### 3. Theme Customization

When customizing PaperMod theme:
1. Make changes in `layouts/` (override theme templates) or `assets/`
2. Test thoroughly
3. Log the change: `python .claude/skills/hugo-log-manager/scripts/add_log_entry.py "Customized [feature]" --type dev --tags theme,design`

### 4. Adding New Sections

When adding new content sections:
1. Create directory in `content/`
2. Update menu in `hugo.yaml`
3. Create necessary layouts if needed
4. Log the change with appropriate details

## Deployment

The site automatically deploys to GitHub Pages via GitHub Actions when:
- Changes are pushed to the `main` branch
- The workflow file is at `.github/workflows/hugo.yml`

## Important Notes

1. **Always log changes**: Use the log management scripts to maintain a clear history
2. **Test locally first**: Run `hugo server` before committing
3. **Keep logs updated**: Log entries should be added immediately after changes
4. **Tag consistently**: Use consistent tags (bug, feature, content, design, config, etc.)
5. **PaperMod is a submodule**: Don't modify theme files directly; use Hugo's override system

## Recommended Tags
